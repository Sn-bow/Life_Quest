# 상태창 중심 안내 페이지 사전 점검 — 2026-09-28

대상은 `docs/index.html`의 **로컬 수정본**이다. GitHub Pages에 게시하거나 Play 등록을 변경하지 않았다. 현재 온라인 페이지와 아래 수정본이 같다고 주장하지 않는다.

## 방문자에게 보여 주는 경계

- 첫 화면의 390×844 앱 이미지는 `docs/rebirth/design/status-system/qa/hunter-window-70xp-ko.png`의 실제 내부 QA 캡처를 JPEG 확장자로 복사한 `docs/site/status-window-development-preview.jpg`다. `70/150 XP`는 테스트 기록이며 새 상태창 버전이 **개발 중**이라고 이미지 설명과 본문에 표시했다.
- 현재 다운로드 버튼은 기존 `v2.0.0-preview.1` ARM64 무료 APK만 가리킨다. 새 상태창과 유료 확장팩이 그 APK에 없음을 버튼 앞, 이미지 설명, 일본어·영어 안내에 명시했다.
- 상태창 확장팩의 외관 3종, 기록 기반 30/90일 보고서, PNG/텍스트/CSV 내보내기를 **판매 예정 기능**으로 설명했다. Play 상품 가격, 비공개 테스트, 판매가 활성화됐다는 문구는 없다. 무료 기본 상태창·퀘스트·XP·원본 기록·백업을 구분했다.
- 개인정보처리방침과 약관의 공개 APK 범위 및 향후 선택적 Google 구매 계정/Play 검증 데이터를 분리했다. 미래 상품의 실제 설정과 데이터 보안 신고는 출시 단계에서 최종 대조해야 한다.

## 확인 결과

| 검사 | 결과 |
|---|---|
| Chrome 게스트의 로컬 HTTP 페이지 | 데스크톱과 반응형 320·400·768 CSS px에서 첫 화면을 확인했다. 320 px에서 두 CTA가 줄을 바꾸고, 다운로드 앵커와 버튼이 화면 밖으로 잘리지 않았다. |
| 페이지 내 링크 | 12개 내부 앵커 모두 대상 ID가 있었다. |
| 로컬 이미지·아이콘 | 참조한 로컬 자산 6개가 존재하고 모든 `<img>`에 `alt` 속성이 있었다. |
| 기존 공개 릴리스 | GitHub 릴리스 페이지와 APK 직접 링크의 HTTP HEAD 응답이 각각 200이었다. 실제 APK 파일 재다운로드나 재설치는 하지 않았다. |
| 정적 검사 | `git diff --check -- docs/index.html` 통과. 사이트에는 추적 스크립트·수제 SVG·Canvas 그림을 추가하지 않았다. |

이번 페이지 수정은 **출시 또는 수익 발생의 증거가 아니다**. 최종 앱 UI가 확정되면 내부 QA 캡처를 해당 버전의 실물 화면으로 교체하고, 공개 전 실제 Play 상품 범위와 개인정보 신고 문구를 맞춘다.
