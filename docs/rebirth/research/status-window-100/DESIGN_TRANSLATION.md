# Life Quest — 내가 여는 상태창

2026-09-27. 레퍼런스 조사에서 도출한 다음 시안의 기준이다. **구현·디자인 승인·출시 완료 문서가 아니다.** 작품에서 확인한 사실과 Life Quest에 대한 설계 제안을 구분한다.

## 제품의 한 문장

**앱을 켜면, 내가 헌터가 되어 내 상태창을 연다.**

이 문장이 첫 화면과 모든 결과 연출을 판단하는 기준이다. 사용자의 이름과 실제 누적 기록이 주인공의 데이터가 된다. 일정은 퀘스트를 만드는 도구이고, 완료한 행동은 내 상태가 변하는 원인이다. 처음 보는 대상은 그날의 할 일 목록이 아니라 나의 상태다.

v8에서 사용자에게 거절당한 이유는 풍경이나 금색의 품질만이 아니다. 도입 카피·배경·추천 목록이 먼저 보이고, 자신의 정보를 조사하고 조작하는 상태 패널이 부차적인 화면에 남아 있었다. 이 정보 위계를 먼저 고쳐야 한다.

## 첫 화면의 정보 위계

아래 순서와 배치는 제안이다. 현행 모델에 없는 데이터를 구현된 것처럼 채우지 않는다.

| 위치 | 내용 | 사용자에게 주는 의미 |
|---|---|---|
| 창의 머리 | 상태창이라는 짧은 표제, 패널 경계, 닫기/재호출 동작 | 내가 시스템을 열었다 |
| 첫 정보 묶음 | 사용자 이름, 레벨, 현재 장착 칭호 | 이 창의 주인은 나다 |
| 성장 행 | 실제 XP 현재값/다음 레벨 기준, 미배분 포인트 | 다음 변화까지 얼마나 남았는가 |
| 중심부 | 네 능력치의 고정된 명칭·수치 행, 항목별 조사/배분 | 나를 이루는 능력이 무엇인가 |
| 아래 요약 | 실제 보유 스킬·칭호, 최근 변화 한 줄 | 내가 얻은 것이 무엇인가 |
| 창 내부 메뉴 | 상태 / 스킬 / 퀘스트 / 기록 | 같은 개인 시스템의 다른 면을 연다 |

폰 화면의 첫 시야에서 이름·레벨·능력치와 창의 경계를 알아볼 수 있어야 한다. 긴 환영 문구, 일러스트 배경의 제목, 추천 퀘스트 여러 장이 이 영역을 차지하면 실패다. 프로필 아바타 커스터마이징은 기존 제외 결정을 유지한다. 사용자 사진이나 전신 캐릭터를 넣어야만 소유감이 생기는 것은 아니다.

새 계정은 실제 초기값과 XP 0을 보여 준다. 기존 계정은 저장된 값이 그대로 나타나야 한다. 앱을 다시 열 때마다 XP를 올리거나, 예쁘게 보이도록 바를 채우거나, 획득하지 않은 칭호·스킬·장비를 넣지 않는다. 사용자에게 지적받은 “늘 경험치가 차 있다”는 인상을 장식 목적으로 되살리지 않는다.

## 창의 네 종류

1. **상태 본체**: 이름·레벨·능력치·보유 정보. 지속적으로 살펴보는 한 장의 패널이다.
2. **조사 창**: 능력치·칭호·스킬을 눌렀을 때 정의, 현재 효과, 획득 조건, 성장 원인을 읽는다. 본체와 공간·프레임을 공유한다.
3. **선택 창**: 돌발 퀘스트의 목표·기한·보상과 수락/거절을 보여 준다. 사용자의 선택으로 상태가 달라진다.
4. **결과 창**: 실제 저장된 XP·포인트·스킬/칭호 변화만 표시한다. 확인 뒤 본체의 같은 항목으로 돌아온다.

모든 창을 독립된 둥근 카드로 쌓지 않는다. 첫 화면 전체가 하나의 시스템이고, 임시 창은 그 위에 등장하거나 그 안에서 전환된다. 퀘스트 목록은 이 체계의 한 화면으로 들어간다.

## 열고 성장하는 경험

| 순간 | 연출 제안 | 실제 동작과 연결 |
|---|---|---|
| 처음 진입 | 짧은 프레임 점등/면의 전개 뒤, 신원→레벨→능력치 순으로 안정 | 저장된 프로필을 읽는다. 첫 등록 설명은 처음에만 한다. |
| 재진입 | 같은 상태창을 즉시 복원하고 짧은 열림 응답 | 새 각성/성장처럼 위장하지 않는다. |
| 능력치 조사 | 누른 행이 강조되고 같은 창에서 세부 정보가 열린다 | 명칭·수치 의미·최근 성장 원인을 보여 준다. |
| 포인트 배분 | 기존값→예정값을 구분하고 적용 버튼으로 확정 | 저장이 성공한 결과에만 획득 연출을 붙인다. 취소 가능 구간을 명확히 한다. |
| 퀘스트 완료 | 결과 제목→실제 보상→변한 항목의 순서로 집중 | 저장된 보상 기록을 단일 근거로 쓴다. 중복 완료에 보상을 재지급하지 않는다. |
| 레벨업 | 일반 완료보다 한 단계 강한 프레임/강조, 레벨 전후·포인트 표시 | 실제 레벨 임계값을 넘었을 때만 발생한다. |
| 돌발 퀘스트 | 짧은 도착 신호와 시스템 창, 명확한 수락/거절 | 거절/만료로 기존 XP나 능력치를 깎지 않는다. 무한 재등장하지 않는다. |
| 기록 열기 | 사건별 결과와 발생 순서를 읽는다 | 완료 원인, XP, 배분 결과를 동일한 데이터에서 재확인한다. |

속도·진동 강도·소리는 작품의 정지 컷에서 검증할 수 없다. 이후 실기 검토할 제안값으로만 다룬다. 열림은 짧고, 필수 기능을 기다리게 하지 않으며, 모션 축소에서는 효과 없이 같은 정보와 조작을 제공한다. 앱을 켤 때마다 긴 부팅 문장·타이핑·로딩 대기를 반복하면 상태를 확인하려는 목적을 해친다.

## 시각 제작 기준

- 배경의 건물·문·던전 풍경을 주인공으로 쓰지 않는다. 상태창 자체의 면, 경계, 내부 정렬, 선택과 변화가 화면의 인상을 만든다.
- 각진 경계와 단정한 정보 행을 우선 탐색한다. 전체 패널의 여백과 탭으로 정보를 묶고, 수치마다 별도의 카드·배지·아이콘을 붙이지 않는다.
- 차가운 계열의 프레임은 현대 헌터 감각을 탐색하는 한 방향이지 필수 정답은 아니다. 무림풍 문양, 특정 IP의 창 모서리, 로고·글자체를 복제하지 않는다.
- 얇은 선과 발광은 보조다. 본문·숫자가 읽히는 어두운 안정 면이 있어야 한다. 읽는 동안 흐림·왜곡·입자가 텍스트를 가리지 않게 한다.
- 장식 bitmap 자산이 필요하면 imagegen 또는 권리가 확인된 무료 자산을 쓴다. SVG/HTML/Canvas로 직접 그린 삽화를 만들지 않는다. 실제 정보·버튼·접근성 텍스트는 Flutter UI로 구현한다. 스크린샷 한 장을 앱 화면으로 붙이지 않는다.
- 참고 작품의 그림을 앱 자산으로 사용하지 않는다. 현재 조사 캡처는 Git에서 제외한 로컬 열람 자료이며 배포 파일에 넣지 않는다.

## 수치의 의미를 먼저 정할 것

헌터의 상태창 느낌을 위해서는 수치가 실제 앱 규칙에 대응해야 한다. 능력치는 사용자가 완료한 행동으로 얻는 **앱 안의 성장 지표**다. 현실 지능·건강·수명을 측정했다는 의미로 표현하지 않는다. 새 HP/MP/랭크/장비를 추가한다면 그 값이 언제 줄고 늘며 무엇에 쓰이는지를 먼저 정의한다. 값이 없는 상태에서는 그럴듯한 숫자를 채우지 않는다.

정체성과 해금도 분리한다. 이름은 사용자 입력, 칭호는 달성 기록, 스킬은 습득 조건, 레벨은 실제 XP 기준으로 설명되어야 한다. 이야기를 읽었다는 이유만으로 현실 행동 XP를 주지 않는 기존 원칙과 거절 무벌점 정책을 보존한다. 수익 기능이나 구매 화면이 첫 상태창을 선점하지 않는다.

- 버튼을 누르면 같은 시스템 안에서 조사·선택·배분이 일어나는가?
- 현실 행동 하나를 완료하면 무엇이 왜 바뀌었는지 본체에서 찾을 수 있는가?
- 재실행해도 실제 값이 유지되고, 성장하지 않았는데 연출만 새로 발생하지 않는가?
- 한국어·일본어·영어, 작은 화면·큰 글씨에서도 이름·수치·명령이 읽히는가?

첫 번째와 두 번째를 충족하지 못하면 장식의 완성도가 높아도 다시 설계한다. 사용자의 원래 표현인 **“사용자가 상태창을 열어보는 느낌”**이 기능 개수보다 앞선다.
