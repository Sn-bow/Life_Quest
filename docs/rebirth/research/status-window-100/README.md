# 내가 여는 상태창 — 105개 IP 레퍼런스 조사

2026-09-27. 사용자가 확인한 제품 기준: **“앱을 켜면 내가 헌터가 되어 내 상태창을 열어보는 것.”**

## 결론

Life Quest의 첫 화면은 사용자의 이름·레벨·능력치·보유 정보가 들어 있는 **한 장의 개인 시스템 창**이어야 한다. 누르면 능력을 조사하고, 포인트를 배분하고, 퀘스트를 열 수 있어야 한다. 현실 행동을 완료하면 시스템이 결과를 알리고 같은 상태창에 변화가 남는다. 배경·꾸밈보다 이 구조가 먼저다.

이 결론은 아래 실제 패널과 본문에서 확인한 ‘소유자/호출/정보/조작/변화’의 조합을 Life Quest에 적용한 **설계 판단**이다. 독자 선호나 상업적 성공을 검증한 사용자 조사 결과는 아니다. 모든 조사 작품이 같은 UI를 쓴다는 뜻도 아니다.

## 실제 조사 깊이

같은 작품의 웹툰·소설·번역 제목은 한 IP로 집계했다. 105개는 **서로 다른 작품 조사 수**이며, 105개 전편 정독 또는 105개 상태창 이미지를 모두 확인했다는 뜻은 아니다.

웹툰 관찰에는 개인 상태표 외에 장비창, 선택 카드, 업적/보상 알림이 포함된다. `+99 Reinforced Wooden Stick`은 강화 확률을 설명하는 만화 문장을 읽은 사례로서, 상태창 외형을 본 사례가 아니다. 소설의 상태 목록 중에는 회차 말 요약이나 머릿속 정보도 있어 각 행의 `unknowns`에 구분했다. `official-system`은 성장 규칙까지 포함하는 넓은 분류이며 UI를 직접 보았다는 등급이 아니다.

헌터 중심 `core-hunter`와 인접 `adjacent`는 조사 편의를 위한 분류다. 무림/VR/현실 퀘스트/이세계/국제 LitRPG를 서로 동일한 장르로 취급하지 않는다. 인접 사례는 조작·정보 분류의 비교에 쓰고, 현대 헌터라는 제품 정체성은 사용자의 요구를 따른다.

`search` 스킬의 분담·출처 검증 절차를 사용했다. 활성 도구에 Exa가 없어 web 검색/페이지 읽기와 브라우저 판독으로 조사했다. notes의 `sources_reviewed`는 각 분담이 실제 연 고유 페이지 수이고, 중복이나 열람 제한 페이지가 있어 단순 합산을 전체 검증 작품 수로 쓰지 않는다.
