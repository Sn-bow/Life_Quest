**6,900원은 확정 가격이 아니다.** 2,900 / 4,900 / 6,900원과 구매하지 않음·미정을 구분해 탐색한다. 앱 조사 응답은 무료 체험에 대한 지불 의향이며 실제 거래·팩 전체의 가치 평가와 별개다. 가격 선택지를 보기 전에 인터뷰에서 기대 가격과 이유를 먼저 묻는다. 선택지 제시로 생기는 기준점 효과도 기록한다.

## 현재 팩의 실제 분량

`python3 scripts/prepare_story_review.py`로 번들 원고를 측정했다. [content-scope.json](content-scope.json)에 원고 SHA256과 산식이 있다. 모든 4,096개 경로에 대해 본문, 고른 선택의 반응, 앞선 선택에 해당하는 반응, 앞선 11선택으로 정해지는 한 결말을 합한다. 공백 포함 Unicode 문자 수이며 UI 제목·버튼은 제외한다.

| 언어 | 한 경로의 실제 서사 문자 수 |
|---|---:|
| 한국어 | 7,896–8,046 |
| 영어 | 14,214–14,462 |
| 일본어 | 5,591–5,696 |
| 중국어 | 4,291–4,365 |

12장면이라는 수만으로 장편이나 높은 가치를 주장할 수 없다. 읽는 시간, 번역 자연스러움, 몰입, 선택의 의미는 미검증이다. 분량을 억지로 늘려 해결하지 않고 전체 원고를 독자에게 검토받는다. 검토용 Markdown은 `qa_artifacts/rebirth/editorial/tide-review-{ko,en,ja,zh}.md`에 생성된다. 내부 검토본을 만드는 것은 앱의 유료 소유권을 부여하지 않는다.

원고는 현재 공개 GitHub 저장소의 개발 브랜치와 앱 번들에 포함되어 있다. 정상 앱의 구매 권한 검사는 원고 자체의 비밀성이나 복제 방지를 보장하지 않는다. 원문을 독점 제공한다고 광고하지 않고, 앱에서 현실 행동과 이어지는 읽기 경험·테마·표식의 가치까지 독자가 납득하는지 확인해야 한다. 콘텐츠 배포 방식은 실제 판매 전에 다시 결정한다.

## 가격을 낮출 때의 비용 회수 조건

아래는 매출 전망이 아닌 비교용 가정이다. 소비자가에 VAT10%가 포함되고, 세전 금액에서 플랫폼 공제가15~30%이며, 콘텐츠 제작·검수 비용을 임의로50만원이라고 가정했다. 실제 세금·수수료·환불·지역별 정산과 다를 수 있다. [Google 수수료 안내](https://support.google.com/googleplay/android-developer/answer/112622?hl=en)와 [변경 일정](https://support.google.com/googleplay/android-developer/answer/16954621?hl=en)을 계정의 실제 조건과 함께 출시 직전에 다시 확인한다.

| 후보 소비자가 | 가정상 판매당 잔여액 | 제작비50만원만 회수할 구매 수 |
|---|---:|---:|
| 2,900원 | 약1,845–2,241원 | 224–271건 |
| 4,900원 | 약3,118–3,786원 | 133–161건 |
| 6,900원 | 약4,391–5,332원 | 94–114건 |

산식은 `가격 ÷ 1.1 × (1 − 공제율)`과 `ceil(500000 ÷ 판매당 잔여액)`이다. 서버·고객지원·환불·번역 유지·유입 비용을 아직 빼지 않았으므로 순이익이 아니다. 가격을 낮추면 필요한 구매 수가 늘어난다. 광고 유입을 사기 전에 실제 제작 단가와 구매 의향의 이유부터 확인한다. 설문에서 비싼 가격을 고른 사람을 구매자로 계산하지 않는다.

## 14일 파일 기반 파일럿

내부 빌드에만 `--dart-define=LIFEQUEST_RESEARCH_ENABLED=true`를 준다. 일반 빌드는 기본 off다. 기기 전용 프로필의 성장 → 설정 → 14일 사용성 테스트에서 **직접 참여**해야 기록이 시작된다. 참여 전에는 식별 코드도 만들지 않는다. 웹에서는 미리보기 자료라는 표시가 붙고 실제 기기 분석에서 제외된다.

- 기록: 무작위 참여 코드, 참여 시점 기준 24시간 구간별 방문/퀘스트 완료 증가 수, 2장면 체험 완료, 선택적 매력·최대 가격 평가, 데이터 이상 표시.
- 제외: 이름, 목표, 퀘스트 원문, 개별 이야기 선택, Google 계정, 구매 영수증, 모델 입력. 정확한 시각은 기기 내부 계산에만 쓰며 결과 파일에는 넣지 않는다.
- 자동 전송과 분석 SDK는 없다. 참가자가 보고서 파일을 직접 저장하고 원하는 경우 전달한다. 개발자가 원격으로 가져오는 기능은 없다.
- 참여 중단 시 테스트 기록만 삭제한다. 기기 프로필 삭제도 테스트 기록을 삭제한다. 이미 전달한 파일은 기기에서 지울 수 없다고 안내한다. 백업에는 연구 기록을 넣지 않는다.
- 완료 수 감소, 백업 복원, 관찰된 시계 역행, 저장 실패는 유지율 분석에서 제외한다. 연구 기록 실패가 퀘스트 수행을 막지 않는다. 직접 기기 파일을 조작하는 행위나 재설치를 통한 새 코드 발급까지 검증하는 부정 방지 시스템은 아니다.
- 14일 후 행동 수집을 종료한다. 앱을 지우거나 보고서를 보내지 않은 사람은 관찰되지 않는다. 전원을 끄고 시계를 변경하는 경우까지 완전히 감지한다고 주장하지 않는다.

### 진행 순서와 판단

1. **5명 내외 관찰 인터뷰:** 첫 행동을 스스로 찾는지, 판타지와 실제 행동을 구별하는지, 팩 체험 후 무엇을 구매한다고 이해하는지 관찰한다. 이름/연락처와 앱 행동 내용을 수집하는 녹화는 기본 요구하지 않는다. 이 수치는 운영 규모 제안이며 시장 표본 기준이 아니다.
2. **최소 12명의 실제 Android 파일럿:** 첫 퀘스트 전에 참여하는 신규 사용자와 기존 사용자를 구분한다. 참여 때 코드만 별도 명단에 적어 누락된 보고서를 확인한다. D1은 24–48시간, D7은 168–192시간 방문이며 각각 48/192시간이 지난 보고서부터 분모에 넣는다. D7 방문과 D7 실제 퀘스트 완료를 각각 본다. 알림으로 돌아온 사용자와 자발적 복귀의 구분은 인터뷰에서 확인한다.
3. **전체 원고 검수:** 한국어 목표 독자 최소 5명, 번역 언어별 검수자를 별도로 구한다. 무료 체험 평가와 전체 원고 평가를 섞지 않는다. 이해되지 않는 장면, 선택의 차이, 분량 만족, 끝까지 읽으려는 이유, 실제 읽은 시간을 기록한다. 모호한 문장과 번역 오해를 수정한 뒤 같은 버전을 다시 평가한다.
4. **다음 실험 진입 기준(임시 내부 가설):** 성숙한 신규 보고서 12개와 참여자 전체 명단이 있고, 그중 최소 6명이 D7에 퀘스트를 완료하며, 전체 원고 검토 5명 중 최소 3명이 이유를 설명하며 후보 가격 하나를 납득할 때 가격 실험으로 넘어간다. 시장 벤치마크나 통계적 수익성 입증이 아니다. 누락 보고서가 있으면 성공 판정하지 않고 원인을 확인한다. 모인 자료를 보고 기준을 사후에 낮추지 않는다.
5. **판매 전 운영 검증:** 실물 AI·저장·접근성, 신고 서버, Play 라이선스 테스트 구매·보류·취소·복원·환불을 모두 확인한다. 테스트 결제는 매출이 아니다. 정책·스토어·콘텐츠 설명이 실제 빌드와 일치해야 한다.
6. **제한적인 실제 판매 실험 여부 결정:** 위 결과, 실제 콘텐츠 제작/번역 비용, 확보 가능한 유입 비용으로 손익 가설을 다시 계산한다. 그때도 매출은 보장할 수 없음을 명시한다. 실험의 예상 손실 한도·가격·대상·중단 기준을 구체화한 뒤 공개 판매 여부를 결정한다. 현재는 이 단계에 도달하지 않았다.

Google Play의 [12명·14일 개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)과 이 사용성 연구는 별개다. APK 설치, 자체 참여 코드 또는 D7 기록을 Play 참여 증거로 대체하지 않는다. 다른 사람에게 모집 메시지는 보내지 않았다.

### 집계 사용법

실제 참여 명단·보고서는 `qa_artifacts/` 또는 별도 비공개 위치에 둔다. Git/PR에 올리지 않는다. 명단은 무작위 코드의 JSON 배열이며 이름·연락처를 쓰지 않는다.

```sh
python3 scripts/analyze_beta_reports.py \
  --roster /private/path/roster.json \
  /private/path/reports/*.json
```

집계기는 신규/기존 사용자, 성숙한 D1/D7, 완료 행동, 체험, 가격 미정/비구매/후보별 의향을 구분한다. 중복 파일을 합치며 기준값 불일치·같은 날 충돌·되돌아간 기록·잘못된 스키마를 보수적으로 제외한다. 미제출자 수와 보고서 커버리지를 함께 낸다. 보고서가 없는 경우 비율은 `null`이며 0%나 성공으로 만들지 않는다. 출력의 판단은 항상 `HOLD_PUBLIC_RELEASE`다. 이 도구 하나로 공개 판매 승인을 낼 수 없기 때문이다.

## 계정과 배포 도구 결정

2026-09-20 Play Console 계정 메뉴와 Firebase Console `u/1`에서 **hyeonseok460**을 직접 확인했다. Firebase CLI `login:list`도 같은 계정이며 `projects:list --account <지정 계정 이메일>`에 프로젝트가 없다. 반면 gcloud 활성 계정은 `hyeonseok45`이었다. **gcloud의 기존 조회 실패는 460 계정 프로젝트 상태의 근거가 아니다.** 45 계정의 다른 프로젝트는 변경하지 않았다.

공식 [Firebase MCP](https://firebase.google.com/docs/ai-assistance/mcp-server)는 Firebase CLI 자격을 사용한다. 계정에 없는 프로젝트를 복구해 주지 않으므로 지금 별도 MCP를 설치할 이유는 없다. 기존 Firebase CLI로 명시적으로 계정을 지정한다. [fastlane supply](https://docs.fastlane.tools/actions/upload_to_play_store/)는 AAB·메타데이터 업로드 자동화에 적합하지만, [Google Play API 접근 설정](https://developers.google.com/android-publisher/getting_started)이 먼저 필요하다. 권한 확대나 새 서비스 계정 키를 지금 만들지 않았다. 실제 출시 조건을 충족하면 기존 도구를 사용해 재현 가능한 업로드 경로를 구성한다.

공개 판매는 보류해도 검토용 APK와 준비 문서의 작성은 계속한다. Firebase 생성/Blaze 연결, Play 상품 활성화, AAB 업로드 또는 공개 심사 제출을 수익성 검증 완료로 오인하지 않는다.
