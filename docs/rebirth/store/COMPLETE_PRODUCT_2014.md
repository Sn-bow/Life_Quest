## 실제 환경 연결 순서

1. Firebase 인증을 **hyeonseok460@gmail.com**으로 완료하고 프로젝트가 `lifequest-crossing-2026`인지 확인한다. 인증 없는 MCP의 Billing 출력은 실제 원격 과금 상태로 읽지 않는다.
2. 운영 Auth 제공자, Firestore/Storage 규칙·TTL·기존 데이터 범위를 먼저 읽는다. 기존 인덱스를 보존하며 필요한 규칙·Functions를 배포한다. App Check를 끄거나 클라이언트에 구매 허용 우회 코드를 넣지 않는다.
3. 구매 검증 런타임 서비스 계정에 이 앱의 Play 구매 확인 권한을 연결한다. 개인 JSON 키를 배포 파일/판매자에게 넘기지 않는다. RTDN `lifequest-play-billing-events`, private acknowledge 큐 IAM, 환불 누락 점검을 연결한다. 최소 인스턴스 예약 없음과 동시 실행 상한, 비용 알림을 확인한다.
4. 검증된 AAB를 **내부** 테스트에 업로드해 패키지·Google 생성 서명 인증서를 확인하고 Firebase/App Check에 해당 인증서를 등록한다. 기존 업로드 인증서를 Play 앱 서명 인증서와 혼동하지 않는다.
5. Complete 상품·지역 가격과 개발자 라이선스 테스트 계정을 설정한다. 일반 크몽 테스터에게 실제 결제를 요구하지 않는다.
6. 아래 거래 시나리오를 Play에서 받은 설치본으로 실행한다. 거래 결과를 확인하기 전 크몽용 비공개 테스트를 완료했다고 표현하지 않는다.
7. 실제 공개 개인정보·삭제 안내와 Console 데이터 보안을 맞추고 비공개 트랙 심사를 제출한다. 심사/활성화 뒤 Console의 실제 참여·설치 URL을 열어 접근 확인한다. seller CSV 등록 후 12명/14일의 시작 여부를 별도로 확인한다.
