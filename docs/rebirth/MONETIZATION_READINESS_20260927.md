# 유료 출시 준비 판단 · 2026-09-27

검토 범위: 현재 저장소의 상품·결제·서버·출시 문서와 공식 정책. 계정 콘솔 재조회, 실제 거래, 시장 반응, 원어민 검수는 이번 감사에서 수행하지 않았다. 기존 무료 공개판을 이번 요청의 완료 단계로 계산하지 않는다.

**판정: 유료 출시를 구현할 기반은 있으나, 현재 배포 파일로 돈을 받는 출시는 불가능하다. 사업의 수익성이 불가능하다고 입증된 것은 아니다. 매출·재구매·제작 원가·고객 획득비 자료가 없어 흑자 가능성은 미검증이다.**

## 소스에서 확인한 기반

- `lib/features/billing/purchase_verifier.dart`: 판매 SKU는 `story_tide_postoffice_01` 하나. 비소모성 상품이며 실거래 가격을 `ProductDetails.price`에서 표시한다. 6,900원은 테스트 fixture/과거 가설이며 실제 확정 가격이 아니다.
- `assets/story/tide_{ko,en,ja,zh}.json`, `TIDE_STORY_PACK.md`: 12장면·두 결말·테마·표식을 단일 권한으로 묶고 첫 두 장면 체험을 제공한다. 유료 장면의 현실 행동 조건은 구매와 별개다. 재미·번역·지불 의사는 아직 검증되지 않았다.
- `functions/purchase_policy.js`: Google 영수증의 상태·계정 해시·수량 검사, 토큰 재사용 차단, Firestore의 원자적 권한 지급, 지급 후 서버 acknowledgment, RTDN 재조회와 환불 권한 회수를 구현했다. Flutter는 서버 검증 실패 시 지급하지 않는다.
- Google 구매 계정은 생활 프로필과 분리한다. Firebase 규칙은 클라이언트의 유료 권한 변경을 금지한다. Billing 8.0.0 의존성을 로컬 Android 패키지에서 확인했다.
- Cloud·Billing 기본값은 off. Ads는 별도 off이며 첫 판매의 수입원에 포함하지 않는다.

## 같은 세션의 보완 결과

앱 종료 후 구매 확인 복구를 private Cloud Tasks 작업으로 구현했고 서버 정책31개가 통과했다. 유료 artifact permission profile도 추가했으며 실제 Cloud/Billing on AAB(versionCode10)의31개 검사와 과금 활성 상품 목록 테스트가 통과했다. 기존 아래 감사의1·2번 코드 문제를 로컬에서 보완한 결과다. 큐/IAM/Functions는 미배포이며 실제 거래는 미검증이다. 상태창 중심 새 유료 혜택과 콘텐츠 제공 방식/환불 정책은 여전히 남아 있다. [화면·빌드·검증 기록](design/status-system/TABLET_RELEASE_REVIEW_20260927.md)을 함께 읽는다.

## 현재 소스에서 보완할 부분

1. **앱 복귀에 의존하지 않는 acknowledgment 재시도.** 지급 후 Google acknowledgment가 실패하면 현재 복구는 클라이언트 재검증에 의존한다. 서버에는 토큰 해시만 저장하고 RTDN 처리도 acknowledgment를 하지 않아 자동 재시도가 완결되지 않았다. 앱이 돌아오지 않아도 처리되는 서버 작업과 실패 감시를 추가하고, 지급 성공→ack 실패→앱 종료→서버 복구를 검사한다. Google은 미확인 구매가 3일 후 자동 환불될 수 있다고 안내한다. 원문 토큰을 로그에 남기지 않으면서 제한된 저장/암호화/보존 기한을 결정해야 한다.
2. **판매용 빌드 검사.** 현재 `scripts/inspect_release_artifact.py`는 기본 무료 artifact에서 BILLING 권한이 없어야 통과한다. Cloud/Billing on·Ads off의 별도 유료 출시 검사와 재현 명령을 만들고 정확한 APK/AAB manifest·서명·권한·SKU를 확인한다. 플래그만 켠 빌드를 거래 검증 완료로 취급하지 않는다.
3. **유료 콘텐츠 제공 방식 확정.** 모든 유료 JSON은 APK와 공개 저장소에 포함된다. 현재 권한 검사는 정상 앱의 통합 경험을 제한하지만 원문 독점 제공은 보장하지 않는다. 독점 원고를 상품 가치로 삼으려면 인증된 콘텐츠 전달과 오프라인 저장으로 바꿔야 한다. 통합 읽기·테마·표식을 판매한다면 그 제공 범위와 위험을 명시한다. 공개된 기존 원고의 비밀성을 복구했다고 주장하지 않는다.
4. **오프라인 소유권의 회수 정책.** 로컬 권한 캐시는 오프라인 이용을 제공한다. 인터넷 연결을 계속 피하는 기기에 환불 회수를 즉시 보장할 수 없다. 영구 오프라인 이용과 회수 지연 사이의 실제 제품 정책을 정하고 안내/검증한다.

## 최소 완성 출시 구조

한 개의 완결 팩 → Play 현지 가격 → 선택적 Google 구매 계정 → Play Billing → App Check가 보호하는 서버 검증 → 원자적 단일 권한 지급 → 서버 acknowledgment 및 자동 재시도 → 읽기/테마/표식 사용 → 복원·환불 RTDN·삭제·지원 운영까지 같은 출시 후보에서 연결한다. 무료 체험이나 내부 초안을 완료 기준으로 사용하지 않는다.

`LIFEQUEST_CLOUD_ENABLED=true`, `LIFEQUEST_MONETIZATION_ENABLED=true`, `LIFEQUEST_ADS_ENABLED=false`의 후보는 위 외부 서비스가 구성되고 거래 검증을 통과한 다음에 출시한다. 외부 설정 전까지 유료 준비 자료와 코드를 완성할 수 있지만 실거래 가능 판정은 남는다.

## 돈을 벌 수 있는지 판단하는 데 남은 근거

유료 상품을 제공하는 기술과 매출이 비용을 넘기는 사업은 각각 검증해야 한다. 경쟁 앱의 가격만으로 우리 앱의 구매 전환을 추정하지 않는다. 현재 수익화의 가장 큰 제품 위험은 상태창을 원하는 고객과 별도 단편을 구매할 고객의 일치 여부, 짧은 원고의 가치, 후속 팩 제작 비용이다.

가격 결정에는 실제 제작/번역/검수 견적, 계정의 실제 세금·플랫폼 공제 조건, 서버/지원 비용, 목표 판매량을 넣는다. 계산은 `필요 구매 수 = ceil((제작비 + 기간 고정비) / (판매당 정산액 - 판매당 변동비))`; 분모가 0 이하이면 해당 가격은 비용을 회수하지 못한다. 기존 `REVENUE_VALIDATION.md`의 가격별 회수 표는 가정 예시이고 실제 손익이 아니다. 실제 구매 전에는 수익성 입증 완료라고 표시할 수 없다.

이번 감사는 파일/문서 읽기와 공식 자료 확인만 수행했다. Firebase/Play 설정, 판매 활성화, 과금 계정 연결, 게시/모집/배포를 실행하지 않았다.

**출시 주력 권고: `status_window_plus_01` 비소모성 일회 구매 ‘상태창 확장팩’.** 기본 상태창·퀘스트·기존 기록은 유지하고 새로 추가하는 ① 선택 가능한 오리지널 상태창 외관 3종 ② 30/90일 능력치 변화와 행동별 기여를 설명하는 성장 분석 ③ 기기에서 저장하는 성장 요약 이미지/파일을 명확한 구매 혜택으로 묶는다. 향후 모든 콘텐츠를 무기한 포함하는 이용권이나 실효과 없는 능력치/XP 판매로 만들지 않는다. 반복 서비스가 아직 없는 현재 단계에는 월 구독보다 고정된 기능의 일회 구매가 운영 부담과 약속을 맞추기 쉽다는 제품 판단이다. 가격은 원가와 실제 상품 품질 확인 후 결정하며 경쟁사 달러 가격을 한국 가격으로 옮기지 않는다.

이는 구현된 상품이라는 의미가 아니다. 현재 판매 조회/서버 상품에는 이 SKU가 없고, 세 외관·기간별 기여 분석·유료 성장 요약 출력도 이 묶음으로 구현되지 않았다. 필요한 작업은 새 혜택 전체 구현 → 기존 무료 혜택을 차단하지 않는 권한 분기 → 메인 상태창의 확장팩 소개/구매/복원 경로 → 4언어 안내 → 앱/서버 SKU와 단일 권한 매핑 → 네이티브 구매·환불·복원 검증이다. 서버 설정만으로 이 상품을 출시할 수 없다.

현재 「조수 우체국」과의 정확한 공백은 다음과 같다.

- 현재 결제는 서가의 별도 이야기에 들어간 뒤 제시된다. 첫 화면의 상태창 약속과 구매 이유가 곧바로 연결되지 않는다.
- Tide는 12장면·책 전용 테마·완독 표식이다. 상태창 외관 선택이나 장기간 성장 분석/출력 권한을 제공하지 않는다.
- 무료 단편을 좋아하는 사람과 상태창을 원하는 사람이 같은 유료 고객이라는 증거가 없다. 새 핵심 SKU는 이 불일치를 줄이는 가설이며 구매 증명은 아니다.
- 기존 Tide ID를 새 상품의 ID로 재사용하지 않는다. Tide는 완성도와 운영 조건을 만족한 뒤 별도 추가 팩으로 남길 수 있다.

따라서 **현재 Tide만 켜는 것은 상태창 중심 유료 앱의 준비 완료로 판정하지 않는다.** 위 확장팩 또는 동등하게 명확한 상태창 중심의 유료 가치를 완성하고 실제 결제 검증까지 연결해야 사용자가 요청한 출시 직전 단계에 해당한다. 이번 문서는 그 제품 방향을 권고하며 판매를 실행하거나 구현 완료를 기록하지 않는다.
