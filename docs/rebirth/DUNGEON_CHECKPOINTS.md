# 탐험 저장 · 2026-09-17

기기 프로필의 `dungeonCheckpoint`에 탐험 ID, 지도/선택한 방, 덱·유물·골드·HP, 일상 보정, 이벤트/상점 진열, 타워 층·배율을 함께 보관한다. 방 입장과 완료, 탐험 종료가 저장 경계다. 전투 중의 손패/턴은 저장하지 않는다. 앱이 종료되면 같은 방의 입장 상태로 되돌아가며, 해당 방에서 아직 확정하지 않은 보상과 지출도 함께 되돌린다. 적은 지도 seed와 방 ID에서 정하므로 재시작 시 바뀌지 않는다.

## 보상과 실패 처리

- 방 안의 변화는 체크포인트를 바꾸지 않는다. 퀘스트나 이름 등 다른 프로필 항목을 저장해도 전투 골드만 미리 기록되지 않는다.
- 최종 보상은 XP·골드·레벨업/업적·구역 해금·타워 진척·`settledDungeonRunId`를 한 프로필 payload에 기록한다. 레벨업 내부의 중간 저장을 이 짧은 동기 처리 동안 억제한다.
- 저장 실패 시 결과 화면에 재시도가 남는다. 같은 실행에서 재시도하거나 저장된 결과 화면에 재진입해도 같은 탐험 보상을 다시 더하지 않는다. 저장 전 종료하면 미수령 결과를 다시 처리한다.
- 수령을 완료하고 홈으로 돌아갈 때 체크포인트를 지운다. 정리 저장이 실패하면 다시 시도할 수 있다. 새 탐험은 진행 중/미수령 결과를 덮어쓸 수 없다.
- 타워는 입장이 아니라 승리했을 때 다음 층을 연다. 타워 승리는 캠페인 구역 해금과 구별한다.
- 손상된 체크포인트는 기존 프로필을 덮어쓰지 않고 복구 화면으로 연결된다. 무료 암호화 파일 백업은 여전히 진행 중인 탐험을 제외한다.

단일 로컬 프로필 쓰기와 수령 ID를 이용한 중복 방지다. 경쟁/서버 경제의 부정행위 방지나 임의 파일 복구·수정에 대한 보장은 아니다. 실제 휴대폰의 저장 공간 부족/프로세스 종료 검증은 출시 전 별도 필요하다.

## 검증

- `test/features/dungeon_checkpoint_test.dart`: 방 도중 종료, 다른 프로필 저장과 간섭, 같은 적/상점/이벤트, 최종 결과 재시작/중복, 디스크 오류 재시도, 이전 프로필의 늦은 쓰기, 타워/신규 탐험 보호, 손상 보존 10개.
- 결과 화면: 4언어 × 성공/실패, 320px / 텍스트 200% 8개.
- 입장·지도·이야기·가입 없는 시작 회귀 테스트.
- Web 실화면에서 발견한 `1 << 32`의 JavaScript 32bit shift 문제를 0x100000000 리터럴로 수정했다. Android VM 단위 테스트만으로 드러나지 않는 경로였다.

CUA로 실제 web release UI에서 HP75/80의 전투 도중 재시작 → 같은 지도/선택 방/초록 슬라임, 입장 HP80/80 복원 → 첫 방 승리(+12 탐험 골드/돌진 카드) → 다음 방 종료 → +15 XP/+8 최종 골드 → 결과 화면에서 다시 시작 → 결과 재진입을 확인했다. 일상 XP는60→75로 한 번만 증가했다. 에뮬레이터/실물 Android UI 검증과는 구별한다.
