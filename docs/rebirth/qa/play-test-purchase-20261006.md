# Play 실서비스의 테스트 카드 구매 확인 — 2026-10-06

본인이 Android 휴대폰에서 `테스트 카드, 항상 승인`을 선택하고 결제 완료를 보고했다. 사용자가 직접 결제했으며 에이전트가 구매 버튼을 대신 누르지 않았다. 실제 금액 청구·매출·고객 구매 수요의 증거가 아니다.

## 이번에 확인한 결과

- Google Play 주문 관리: Life Quest Complete `quest_journeys_complete_01`, **‘테스트’ 표시와 ‘처리됨’**, 10/6 05:37 UTC(한국14:37). 주문 상세 기록에서도 접수05:37:22 UTC·처리05:37:23 UTC와 **예상 수익0원**을 확인했다. 6,500원은 상품의 표시 가격이며 이 테스트 주문의 실제 청구·매출로 계산하지 않는다. 주문 번호는 공개 기록에 남기지 않는다.
- Firebase MCP의 지정460 인증과 `lifequest-crossing-2026` 프로젝트를 확인했다. 별도 gcloud CLI 인증은 사용할 수 없었고, 재로그인을 요청하지 않고 이미 인증된 Firebase MCP로 조회했다.
- 실제 구매 계정 준비 및 구매 검증 callable에서 `auth: VALID`, `app: VALID` 로그를 확인했다. App Check를 우회하거나 수동 권한을 삽입하지 않았다.
- Firestore `purchaseTokens`를 `productId/state/verifiedAt/uid`만 마스킹해서 읽었다. Complete 구매 상태 **purchased**와 서버 검증 시각 **05:38:43.864 UTC**를 확인했다. 구매 토큰 원문이나 구매키는 읽거나 저장하지 않았다. UID는 동일 권한 문서를 조회하는 데만 사용하고 이 문서에 기록하지 않았다.
- 해당 계정의 Complete 권한을 `productId/entitlementId/active/source/verifiedAt/grantedAt/revokedAt`만 읽었다. **active=true, source=google_play**, 최초 부여05:37:35.237 UTC, 최종 확인05:38:43.864 UTC. 무료 기록이나 목표 본문은 조회하지 않았다.
- RTDN 수신05:37:24.102 UTC, 구매 검증 요청05:37:47.903 UTC, 승인 복구 작업05:38:34.387 UTC. 승인 복구 작업의 HTTP200/204 필터에서 정상 완료를 확인했다. 해당 구간의 구매 검증·승인·RTDN HTTP400이상 로그는 없었다. Play API의 `acknowledgementState`를 토큰으로 직접 조회한 것은 아니므로 해당 필드 자체를 확인했다고 주장하지 않는다.
- **휴대폰 구매 복원 사용자 보고:** ‘구매가 확인되었습니다. 콘텐츠를 이용할 수 있습니다’가 표시됐고, 상태창 외관/보고서에서 ‘확장팩을 보유중입니다. 구매 내역으로 확인된 외관과 기록 기능을 사용할 수 있습니다’를 확인했다. 휴대폰 화면을 도구로 직접 촬영한 증거는 아니며 사용자 보고다.
- **복원 이후 서버 확인:** 동일 계정의 마스킹된 Complete 권한이 active=true/source=google_play이고 verifiedAt은05:52:53.361 UTC(한국14:52:53)로 갱신됐다. 구매 검증 callable05:52:44.530655·05:52:52.224009 UTC에서 auth/app VALID, 해당 복원 구간의 구매 관련 HTTP400이상 로그 없음.

## 환불 검증 준비

해당 테스트 주문의 환불 양식만 열어 **자격 삭제 체크·100%·사유 기타**로 준비하고 최종 버튼을 사용자에게 인계했다. 브라우저에서 금융 작업의 최종 실행은 사용자 인계 대상이라는 컴퓨터 사용 규칙을 적용했다. 로컬 `build/review/play-test-refund-prepared-20261006.png`는 준비 당시 양식의 상품/권한 영역을 캡처했고 주문 번호는 제외했다. Git에 이미지를 추가하지 않는다.

사용자는 내부 QA의 계속 진행을 재승인했고 외부 테스터 모집용 비공개 테스트 배포는 앱 완성/준비 상태를 먼저 보고할 때까지 보류했다. 환불 QA를 비공개 트랙 게시로 확대하지 않는다.

## 테스트 환불과 서버 권한 회수 확인

- 사용자가 최종 환불 버튼을 직접 누르고 ‘환불 완료’를 보고했다. 에이전트가 대신 확정하지 않았다.
- 같은 Play 테스트 주문의 상태 **환불됨**, 처리 기록 **06:00:35 UTC(한국15:00:35)**, 합계·예상 수익0원 확인.
- 동일 마스킹 영수증이 **state=revoked**, Complete 권한이 **active=false/source=google_play**로 바뀌었고 verifiedAt은 **06:00:45.737 UTC**다. 구매 토큰 원문·주문 ID·사용자 기록을 읽거나 직접 권한 문서를 수정하지 않았다.
- 정확한 함수 `onPlayPurchaseNotification`의 요청06:00:36.652257/06:00:36.776086 UTC가 HTTP200/204 성공 필터에서 확인됐고 해당 환불 구간의 RTDN/구매 검증/승인 함수 HTTP400이상 로그는 없다. 처음 사용한 `playPurchaseNotification`은 대상이 다른 필터여서 빈 결과를 근거로 삼지 않고 소스 export의 실제 함수명으로 다시 확인했다.
- 서버 권한 회수는 확인했지만 휴대폰 유료 UI 잠금과 무료 기록 보존은 별도 사용자 확인을 요청했다.

## 아직 확인해야 하는 결과

1. 환불 후 휴대폰에서 온라인 재실행/구매 복원한 뒤 유료 기능 잠금과 무료 진행·기존 메모/도구 기록 보존. 확인 질문에 답변 대기다.
2. 휴대폰의 실제 앱 버전. 내부 트랙에2017은 게시했지만 이번 사용자의 보고에는 버전 숫자가 포함되지 않았다. 버전 질문에 답변 대기이며 이 서버 검사로 최신 Android 화면 전체 QA까지 확인했다고 표현하지 않는다.
3. 거절/보류 결제 시 유료 기능이 열리지 않는지. 이번 항상 승인·복원·환불 테스트와 구분한다.

로그 원문·계정 ID·주문 ID·영수증·구매 토큰은 공개 파일에 복사하지 않았다. 본인 테스트 결제 성공을 제품 전체 완성·수익성 검증·크몽 비공개 테스트 완료로 대체하지 않는다. 다음 단계는 [본인 휴대폰 절차](../store/OWNER_BILLING_QA_2017.md), 최신 상태는 [CONTINUE](../CONTINUE.md)를 따른다.
