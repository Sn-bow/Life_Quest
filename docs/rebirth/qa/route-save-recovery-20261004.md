# 루트 저장 실패 복구 · 2026-10-04

Play 권한·실제 기기 입력 대기는 결제 검증의 대기 조건이다. 제품 자체를 검토하고 수정하는 작업의 중단 조건으로 사용하지 않는다. 사용자 목표와 디자인을 변경하지 않았다.

## 재현한 결함

1. 루트 시작 저장 실패 후에도 생성한 루트가 메모리에 남았다. 다시 시작할 때 사용자가 새로 입력한 목표 대신 실패했던 목표를 재사용할 수 있었다.
2. 목표 이름/활성 루트 변경 또는 미션 수락 실패 후에도 변경 상태가 남았다. 평소 미션 수락 실패 후 작은 행동을 선택해 재시도하면 이전 미션이 반환될 수 있었다.
3. 저장 실패 때 메모리만 되돌리면, 동시에 대기 중인 자동 저장이 실패한 값을 다시 파일에 쓸 수 있었다. 실제 재시작 검사에서 이전 목표 대신 실패한 목표가 복구됨을 확인했다.

## 수정

- 여섯 루트 변경 경로에 공통 실패 복구를 적용했다. 성공한 저장 전에 실패하면 기존 루트/미션을 복구하고, 이후 추가된 관련 없는 퀘스트는 유지한다.
- 일반 저장은 진행 중인 루트 변경의 성공/복구가 결정된 뒤 스냅샷을 만든다. 실패한 변경이 다음 저장으로 부활하지 않게 한다.
- 계정 세대가 바뀌었을 때 이전 상태를 새 프로필에 덮어쓰지 않는다. 새로운 프로필의 진행 중인 저장 장벽도 이전 작업이 해제하지 않는다.
- 도구 수정과2분 행동 변경의 별도 복구 코드를 공통 경로로 통합했다. XP 보상 완료의 기존 중복 방지·재시도 방식은 바꾸지 않았다.
- 전체 검사에서 공개 안내의 후보 버전이2016으로 남은 것을 발견해 로컬 안내 소스를2017로 맞췄다. 공개 사이트를 배포한 것은 아니다.

## 근거와 범위

`test/features/journeys_test.dart`의 새로운3개 회귀 검사에서 수정 전 실패를 확인했다. 생성/목표/선택/수락 실패, 다른 선택으로 재시도, 재시작, 자동 저장 겹침과 별개 퀘스트 보존을 검사한다. 초기 관련40개 및 Cloud/Billing on 관련37개가 통과했고 정적 분석 문제는 없다. 최종 전체 검사·빌드는 CONTINUE의 최신 항목과 해당 메타데이터를 따른다.

이 문서는 코드와 저장 경계 검사다. 새 디자인 감사·실제 Android UI 조작·Play 구매·복원·환불·고객 구매 수요를 확인한 자료가 아니다. 기존2016본인 내부 게시와2017제품 코드의 차이를 유지하며 전체 목표 완료를 선언하지 않는다.
